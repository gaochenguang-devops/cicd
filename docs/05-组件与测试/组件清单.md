# 七套系统的作用与说明（GitLab / Keycloak / Jenkins / Harbor / SonarQube / Artifactory / ArgoCD）

平台上有 7 套对外服务，加上 OpenLDAP 和 GitLab Runner 两个不直接面对开发者的支撑件，共同组成"提交 → 检查 → 构建 → 存档 → 上线"的一条链。

> 监控栈（Prometheus / Alertmanager / Grafana / blackbox / 钉钉桥）不属于这七套业务系统，单独见 `docs/04-可观测与告警/可观测性.md`。

本文按**数据流顺序**讲（和你列举顺序略有不同），因为这样最容易理解"每一环为什么必须存在"：代码从 GitLab 出来，身份由 Keycloak 统一签发，Jenkins 是可选的第二条流水线，构建产物进 Harbor、质量结论进 SonarQube、交付制品进 Artifactory，最后 ArgoCD 把它们落到 K8s 上。

## 0. 一眼看懂：谁解决什么问题

| 系统 | 一句话作用 | 不用它会怎样 | 本实例地址 |
|---|---|---|---|
| **GitLab** | 代码托管 + CI 编排 + 权限与评审 | 没有唯一代码源，改了什么、谁改的、能不能合，全靠口头 | `http://192.168.200.12`（80） |
| **Keycloak** | 统一身份入口（SSO），把 LDAP 账号换成各系统能用的 token | 每套系统各一套账号密码，人走号还在，权限对不齐 | `:30087` |
| **Jenkins** | 通用流水线引擎（备选执行器） | 只能用 GitLab CI；非 Git 触发的任务（定时、跨系统编排）没地方跑 | `:30088`（agent `:30089`） |
| **Harbor** | 私有镜像仓库，K8s 唯一的 image 来源 | 镜像没处存，Pod 只能去外网拉，断网即不可部署 | `:30090` |
| **SonarQube** | 静态代码扫描 + 质量门禁 | 漏洞、坏味道、重复代码没人拦，只能等出事 | `:30091` |
| **Artifactory** | 通用制品仓库（二进制交付物） | 只存镜像不存"交付件"，无法回答"这次上线到底发了什么" | `:30092`（备用 `:30100`） |
| **ArgoCD** | GitOps 部署器，把清单变更落到 K8s | 靠人 `kubectl apply`，集群里实际跑的和仓库里写的会越走越远 | `:30080`；中文 `:30082` |

支撑件：**OpenLDAP**（`:389`，账号与组的唯一真源，phpLDAPadmin 在 `:8090` 管人）、**GitLab Runner**（执行 CI job，注册在宿主上）。

## 1. GitLab —— 代码与流水线的起点

**一句话**：整个平台的"事实起点"。代码在这里、变更在这里评审、流水线定义（`.gitlab-ci.yml`）也在这里。

**它解决什么**：一处代码源 + 一套权限。谁可以推 main、谁只能推分支、谁能改流水线文件、谁能看 deploy 分支，都是 GitLab 的职责范围。它还顺带承担了"触发者"角色——push 之后该跑什么、跑完把结果写到哪，由它驱动。

**核心概念**

| 术语 | 在这里的含义 |
|---|---|
| 项目（Project） | 一个仓库 + 一套 CI 配置 + 一套成员权限。本平台有 `root/podinfo`（主业务）和 `root/cicd-demo`（演示） |
| 分支 `main` / `deploy` | `main` 放源码与 CI 定义；`deploy` 是 **orphan 分支，只放清单**（`deploy/*.yaml`），ArgoCD 只读它。这是本平台最关键的一条边界 |
| Pipeline / Stage / Job | 一次 push 触发一条 pipeline，含 4 个 stage（`quality` → `build` → `artifact` → `manifest`），每个 stage 下若干 job |
| CI/CD Variables | 存 `HARBOR_USER` / `HARBOR_PASS` / `SONAR_TOKEN` 等。注意 `$` 会被二次展开，robot 账号要写成 `robot$$apps+ci-builder` |
| PAT | 个人访问令牌，脚本/ArgoCD 用它代替登录。本平台 `${GITLAB_PAT}` |
| Webhook | push 后通知 ArgoCD（`/api/webhook`），秒级同步；另有 3 分钟轮询兜底 |
| Runner | 执行 job 的进程。宿主上以 `gitlab-runner` 服务运行，标签 `shell`，走宿主 docker/containerd |

**本实例配置**

- GitLab CE，el10 原生包（`gitlab-ctl` 管理），数据在 `/var/opt/gitlab`
- `ldap_enabled=false`：**不再直连 LDAP**，登录走 Keycloak 的 `openid_connect`
- 16 个用户 = 12 个 LDAP 账号 + `root` + `GitLabDuo` + `lead02`（历史悬空）+ `ghost`
- 3 个组；`developers` 对应 Developer、`platform-admins` 对应 Maintainer/Owner 级别（CE 无 LDAP 组同步，靠 `ldap-gitlab-sync.sh` + timer 补齐）
- 镜像 tag 只推**全 40 位 sha**，不推 `latest`；回写 `deploy/` 清单由 CI 完成

**你会用到它做什么**

- 看这次提交为什么没过：CI/CD → Pipelines → 点进 job 看 trace
- 临时改流水线：改 `.gitlab-ci.yml` 走 MR；改 deploy 清单不要手推，走流水线
- 加人/调权限：Settings → Members；批量同步交给 LDAP 脚本
- 回滚：在 `deploy` 分支把镜像 tag 改回上一个 sha（见 `02-流水线与交付/GitOps与ArgoCD.md` 第 8 节）

**验证命令**

```powershell
python scripts\tools\ssh_exec.py "curl -s -o /dev/null -w '%{http_code}' http://192.168.200.12/-/health"
python scripts\tools\ssh_exec.py "curl -s -H 'PRIVATE-TOKEN: ${GITLAB_PAT}' 'http://192.168.200.12/api/v4/projects/2/pipelines?ref=main&per_page=3'"
```

**注意**：`deploy` 分支一旦被人手工 push，GitOps 的唯一写入者假设就被破坏；`.gitlab-ci.yml` 里对 `deploy` 的写权限应只留给 CI 的 token。

## 2. Keycloak —— 统一身份入口

**一句话**：把 LDAP 里的"人"，换成每套系统都能验的 OIDC token。

**它解决什么**：认证协议碎片化。GitLab 认 LDAP、Harbor 认 LDAP 组、Jenkins 认 LDAP、ArgoCD 认 Dex、Sonar 认 GitHub/OIDC、Artifactory 认 LDAP——每接一套都要写一遍绑定参数、踩一遍组映射的坑。Keycloak 出现后，只有它连 LDAP，其余系统只认 OIDC，账号、组、会话收敛到一个地方。

**核心概念**

| 术语 | 含义 |
|---|---|
| Realm | 身份域，本平台是 `corp`（UUID `b145c645-…-ec765bc46ba2`），所有 client 都建在它下面 |
| Client | 一个接入方，本平台有 `gitlab`、`jenkins`、`harbor`、`sonarqube`、`artifactory`、`argocd-dex`、`cli-test` |
| User Storage（LDAP 联邦） | `corp-ldap`，`READ_ONLY`，从 OpenLDAP 同步人与组，10 分钟一次 |
| Group Mapper | 把 LDAP 的 `memberOf` 映射成 token 里的 `groups` 声明，各系统靠它判权限 |
| Client Scope `groups` | 让 token 真正带上组名，缺了它所有系统都"认得出人、认不出角色" |

**本实例配置**

- `:30087`，`admin` / `${KEYCLOAK_ADMIN_PASS}`，realm `corp`，12 用户、4 组（与 LDAP 一致）
- 组件用 Postgres（`:5432`，`sonar`/`keycloak` 两个库同实例不同库），数据 `/data/keycloak`
- 全链路 HTTP（无 TLS），回调均已写死 `http://192.168.200.12:xxxx/...`

**你该知道的边界**

- Keycloak 是**单点**：它挂了，所有人新登录都失败（已登录会话按 token 有效期还能撑一会儿）。监控已覆盖它（Prometheus `KeycloakDown` 规则 + `keycloak-metrics` 抓取，2026-11-27）；**备份与恢复演练仍是缺口**，所以它依旧排第一
- `artifactory` client 建了但没用（Artifactory OSS 版不支持 OAuth/SAML，最终走 LDAP 直连）——**不是漏配，是版本能力限制**
- 组权限判定的正确姿势是看 token 的 `groups`，不要依赖 `realm_access.roles`

**验证命令**

```powershell
python scripts\tools\ssh_exec.py "curl -s -o /dev/null -w '%{http_code}' http://192.168.200.12:30087/realms/corp/.well-known/openid-configuration"
python scripts\tools\ssh_exec.py --script scripts\keycloak\423-group-mapper.sh --timeout 90
```

## 3. Jenkins —— 备用的通用流水线引擎

**一句话**：一条"不依赖 Git push"的流水线，用来跑定时、跨系统编排、需要交互式参数的任务。

**它解决什么**：GitLab CI 的触发模型是"代码变了就干活"。但真实运维里还有另一类任务——每天凌晨拉一次基线做回归、批量重建镜像、跨系统对账、需要人填参数才跑的脚本。这些放 GitLab CI 里不合适，Jenkins 是这类任务的落点。

**诚实说明现状**：本平台**实际在跑的流水线是 GitLab CI**，Jenkins 目前是"已部署、可登录、能跑 Job"的备用执行器，两者尚未串成一条链。`docs/02-流水线与交付/Jenkins部署.md` 第 8 节给了把它接进 Sonar/Artifactory 的 Jenkinsfile 片段，需要时可以照着接。

**核心概念**

| 术语 | 含义 |
|---|---|
| JCasC（Configuration as Code） | 全部配置写在 ConfigMap `jenkins-casc` 里，改配置 = 改 YAML + reload，不点 UI |
| `oicSecurityRealm` | 现用认证方式（Keycloak OIDC），client `jenkins`，`groupsFieldName: groups` |
| `globalMatrix` | 全局授权矩阵的 JCasC 键名；写成 `matrix` 会直接启动崩溃（踩过） |
| Break-glass | 应急本地账号 `breakglass / ${JENKINS_BREAKGLASS_PASS}`，OIDC 挂了还能进 |
| numExecutors=2 | 内置 agent 并发 2；独立 agent 在 `:30089` |

**本实例配置**：`:30088`，home `/data/jenkins`（hostPath PV 10Gi），镜像 `192.168.200.12:30090/library/jenkins:lts-jdk21`，权限按 `groups` 声明给（`platform-admins` → Administer）。

**你会用到它做什么**：改 JCasC 后 reload、验证登录与权限、接新 Job。

```powershell
python scripts\tools\ssh_exec.py --script scripts\jenkins\338-reload-casc.sh      # 改完 ConfigMap 后热加载
python scripts\tools\ssh_exec.py --script scripts\jenkins\340-verify-oidc.sh      # 验证 OIDC 与 groups
```

**注意**：切 OIDC 之后**表单登录已不可用**，脚本化访问只能走 `securityRealm/commenceLogin` 或 API Token；UI 上点登录会跳 Keycloak，这是预期行为。

## 4. Harbor —— 私有镜像仓库

**一句话**：集群里每一个 Pod 的镜像都从它来，是"能部署"和"不能部署"的分界线。

**它解决什么**：外网依赖与供应链可控性。镜像一旦进 Harbor，就是不可变的一层保障：断网能部署、能追到某个 sha 是谁编的、能被 K8s 用 imagePullSecret 拉到。同时它是**门禁 1**的执行点——镜像推不上去，后面的回写与部署全部不会发生。

**核心概念**

| 术语 | 含义 |
|---|---|
| Project | 命名空间。`apps`（业务镜像）、`library`（基础镜像） |
| Repository / Tag | `apps/podinfo` 下每个 tag = 一次提交的不可变镜像（13 个历史 tag，约 4.0 GB） |
| Robot Account | 给 CI 用的机器账号 `robot$apps+ci-builder`；在 GitLab 变量里必须写 `robot$$apps+ci-builder` |
| OIDC / LDAP 组 | 现 `auth_mode=oidc_auth`；项目成员按**组**授予（`group_type=1`）而不是按人 |
| Retention | tag 保留策略，回滚能力全靠它，必须配"保留最近 N 个" |

**本实例配置**：`:30090`，Helm 安装，`admin / ${HARBOR_ADMIN_PASS}`，`apps` 项目成员实测为 `admin(projectAdmin)` + `developers(developer)` + `devops(maintainer)` + `qa(guest)`（早期手工加的 `dev01` 个人成员已不在）；数据 `/data/harbor` 4.0 G。

**你会用到它做什么**

- 查某次部署用的镜像在不在：Projects → apps → podinfo → Tags
- 配 robot 权限、调 tag 保留（**优先做这件事，它决定能不能回滚**）
- 排查 `ImagePullBackOff`：先看 imagePullSecret 有没有、再确认 tag 存在

```powershell
python scripts\tools\ssh_exec.py "curl -s -u 'robot\$apps+ci-builder:<pwd>' 'http://192.168.200.12:30090/v2/apps/podinfo/tags/list'"
python scripts\tools\ssh_exec.py --script scripts\harbor\72-harbor-smoke.sh --timeout 200
```

**注意**：Harbor 走 OIDC 后，`ldap_auth` 时代那套组继承配置已失效，成员要按 OIDC 组重授；`docs/03-身份与账号/OpenLDAP目录.md` 4 节记了这段历史。

## 5. SonarQube —— 代码质量门禁

**一句话**：在镜像构建**之前**插一道闸，代码不达标就不给你编。

**它解决什么**：把"质量"从上线后的 bug 变成提交时的失败。它的输出不是报告给人看的，而是一个可判定的 `quality gate status`——`OK` 放行，`FAILED` 让 job `exit 3`，整条 pipeline 停在第 1 个 stage。

**核心概念**

| 术语 | 含义 |
|---|---|
| Project | 一个被分析对象，本平台是 `podinfo`（`sonar.projectKey`） |
| Quality Gate | 一组阈值条件，本平台自建 `cicd-gate` 并设为默认 |
| New Code 条件 | 只看"新增代码"，这样老代码的历史债务不会一上来就拦死新提交 |
| Rating 值 | A=1、B=2、C=3、D=4、E=5；条件是"劣于某级"，所以 `GT 3` 表示"比 C 差（即 D/E）才拦" |
| `sonar-scanner` | 扫描器，跑在 CI 的 `quality` stage，镜像来自 `library/sonar-scanner-cli` |
| CI Token | `squ_…`，挂在 `admin` 用户名下，`SONAR_TOKEN` 变量用它 |

**本实例配置**

- `:30091`，`sonarqube:10.7-community`，数据 `/data/sonarqube`（403 M）
- `cicd-gate`：`new_security_rating > 3`、`new_reliability_rating > 3`、`new_coverage < 1`（当前形态是"只拦 D/E 级"，偏宽松，见下方"该不该收紧"）
- `sonar.forceAuthentication=true`：匿名 API 一律 401，脚本必须带令牌
- 本地应急管理员 `sonaradmin / ${SONAR_ADMIN_PASS}`（原 `admin` 的本地密码已失效）
- 插件只认 `sonar-auth-oidc-plugin-2.1.1.jar`（3.0.0 要求插件 API 11，容器起不来）

**它在本平台的位置**：pipeline 的**门禁 0**，比"镜像能不能拉"更早。首轮实测确实拦下过（`new_security_rating=3`、`new_reliability_rating=3` → `FAILED`、`exit 3`），阈值校准后才转绿——这条证据在 `05-组件与测试/验收测试用例.md` TC-33/TC-34。

```powershell
python scripts\tools\ssh_exec.py "curl -s -u sonaradmin:'${SONAR_ADMIN_PASS}' 'http://192.168.200.12:30091/api/qualitygates/project_status?projectKey=podinfo'"
```

**该不该收紧**：现为 `GT 3`（宽松）。若团队能接受"首轮补齐"，把 `error=3` 改成 `1` 就是 A 级门槛，`scripts\sonar-jfrog\996-sonar-gate2.sh` 改完重跑即可。这是需要人拍板的取舍，不是技术限制。

## 6. Artifactory —— 通用制品仓库

**一句话**：把"这次上线到底发了什么"变成一个可下载、可校验的二进制。

**它解决什么**：镜像只说明"容器长什么样"，回答不了"交付物是什么"。制品库负责这层：`podinfo` 二进制 + 同名 `.sha256`，两端 hash 一致即证明"编出来的和部上去的是同一个东西"。审计、回滚取证、给客户交付，都靠它。

**核心概念**

| 术语 | 含义 |
|---|---|
| Repository | `build-artifacts`，Local + Generic 类型，路径规则 `<project>/<branch>/<sha>/…` |
| Router | 7.x 的 UI/access API 走 **8082**，不是 8081——本平台为此单开了 Service `:30100` |
| `api/storage` | 查文件是否存在、大小、sha256；只走 `/artifactory/api/...` + Basic |
| OSS 限制 | REST 建仓 400、OAuth/SAML 灰置、`api/security/groups` 不可用——都只能 UI 操作 |

**本实例配置**：`:30092`（UI `/ui/`）+ 备用 `:30100`，`artifactory-oss:7.104.7`，`admin / ${ARTIFACTORY_ADMIN_PASS}`，数据 `/data/artifactory`（109 M，只存制品不存镜像）。**它是唯一还直连 LDAP 的系统**（`corp-ldap`，Group Member Attribute 必须 `member`，STATIC）。

**它在本平台的位置**：`artifact` stage。`ci/publish-artifact.sh` 打包上传并写一行纯 hash 的 `.sha256`（不是 `sha256sum` 的两段格式，`sha256sum -c` 会报格式错——踩过）。

```powershell
python scripts\tools\ssh_exec.py "curl -s -u admin:'${ARTIFACTORY_ADMIN_PASS}' 'http://192.168.200.12:30092/artifactory/api/storage/build-artifacts/podinfo/main/<sha>'"
```

**三个不要试**：不要用 REST 建仓、不要指望 OSS 版给组配权限、不要用 `/access/api/...`（三种鉴权全失败）。要建组、挂权限目标，只能在 UI 里点。

## 7. ArgoCD —— GitOps 部署器

**一句话**：集群里"应该跑什么"只由 Git 里写什么决定，它负责把两者对齐。

**它解决什么**：命令式部署的漂移。`kubectl apply` 之后没人知道线上和仓库差多少；ArgoCD 把 `deploy` 分支当唯一期望状态，持续比对、自动收敛，界面直接告诉你 `Synced/OutOfSync`、`Healthy/Degraded`。

**核心概念**

| 术语 | 含义 |
|---|---|
| Application | 一份"仓库路径 → 集群命名空间"的映射。本平台 2 个：`podinfo`、`webapp`，**都指 `targetRevision: deploy`** |
| Sync Policy | `automated{prune, selfHeal}`：自动同步、删多余资源、被手改后自动纠回 |
| Dex | ArgoCD 自带的身份代理。现在它的 connector 配成 `oidc` → Keycloak（client `argocd-dex`），不是直连 LDAP 了 |
| Refresh | REST 没有 refresh 端点，用 `kubectl annotate … refresh=hard` |
| 中文层 | `:30082` 是 nginx 代理 + 词库注入，改词库需 `rollout restart`（`subPath` 不跟随 ConfigMap） |

**本实例配置**：原生 `:30080`，中文 `:30082`，`admin / ${ARGOCD_ADMIN_PASS}`，`server.insecure=true`（HTTP）。两个 Application 的清单都在 `deploy/` 下，镜像 tag 由 CI 回写。

**它在本平台的位置**：链尾。CI 写完 `deploy` 分支 → webhook 通知 → 它拉取并同步（秒级；webhook 失效时靠 3 分钟轮询兜底）。

```powershell
python scripts\tools\ssh_exec.py "kubectl -n argocd get applications"
python scripts\tools\ssh_exec.py --script scripts\argocd\101-argo-health.sh --timeout 90
```

**注意**：**不要**在集群里 `kubectl edit` 被 ArgoCD 管的资源——selfHeal 会把你改回来。要改就改 Git。

## 8. 串起来：一次提交走过谁

```
git push (main)
   │
   ├─① GitLab 触发 pipeline
   │
   ├─② quality   ──→ SonarQube 扫描 → cicd-gate 判定（FAILED 即停）
   │
   ├─③ build     ──→ Runner 构建 → 推 Harbor（门禁 1：镜像可读）
   │
   ├─④ artifact  ──→ 打包上传 Artifactory + 写 .sha256（门禁 2：HEAD 判定）
   │
   ├─⑤ manifest  ──→ 回写 deploy/ 里的镜像 tag（提交到 deploy 分支）
   │
   └─⑥ ArgoCD 收到 webhook → 拉 deploy 分支 → 同步 Pod
```

身份在这条链上出现两次：人登录 GitLab（Keycloak）、Runner 登录 Harbor（robot account）。Jenkins 不在这条链上，它是**并联**的另一条执行路径。

## 9. 职责边界速查

| 问题 | 该找谁 |
|---|---|
| 代码为什么没合、谁改了流水线 | GitLab |
| 登录不了 / 登录后没有管理员权限 | Keycloak（再看 LDAP 组） |
| 镜像推不上去 / Pod 拉不到镜像 | Harbor |
| 提交被拦、扫描报了什么 | SonarQube |
| 这次上线发了哪个文件、对不对 | Artifactory |
| 线上和仓库不一致 / Pod 没更新 | ArgoCD |
| 定时任务、跨系统编排 | Jenkins |
| 新人加号、调组、清退 | OpenLDAP（+ `ldap-gitlab-sync.sh`） |

## 10. 认证矩阵（当前形态）

| 系统 | 登录方式 | 组从哪来 |
|---|---|---|
| GitLab | Keycloak OIDC（`openid_connect`，`ldap_enabled=false`） | CE 无组同步，`ldap-gitlab-sync.sh` 每 10 分钟补齐 |
| Harbor | Keycloak OIDC（`auth_mode=oidc_auth`） | OIDC `groups` 声明 → 项目按组授予 |
| Jenkins | Keycloak OIDC（`oicSecurityRealm`） | `groups` → `globalMatrix` |
| SonarQube | Keycloak OIDC（`sonar-auth-oidc-plugin`） | OIDC groups → Sonar 组 → 权限模板 |
| ArgoCD | Dex 的 `oidc` connector → Keycloak | `groups` → `policy.csv` 的 `role:` 映射 |
| Artifactory | **LDAP 直连**（`corp-ldap`，唯一例外） | LDAP 组（权限目标尚未映射，待做） |
| Keycloak 自身 | 本地管理员 + LDAP 联邦 | — |
