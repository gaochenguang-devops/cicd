## 3. 还有哪些「可能泄露」的东西（不是口令）

这些属于**内部架构披露**：口令泄漏了能直接登录，这些泄漏的是「你有一套什么样的内网」。公开到 GitHub 会被别人看到：

| 类别 | 规模 | 例子 | 风险 |
| --- | --- | --- | --- |
| 内网地址 | `192.168.200.12` 约 694 处 | IP、NodePort 段（30080–30100）、VIP `192.168.200.210` | 暴露内网规划；对公网无直接危害 |
| 内部域名 / CA | `*.corp.local` 约 631 处 | 13 个域名、`CORP Internal CA` 指纹 | 可被用来做社工/钓鱼铺垫 |
| 账号命名与角色 | 十几处 | `robot$apps+ci-builder`、`dev01..qa02`、组 `platform-admins` | 暴露组织与权限模型；`robot$` 在 bash 双引号里还会被 `$apps` 展开，抄命令易出错 |
| 运维叙述 | 全文 | 越权遗留账号、口令过期、白名单被绕过、漏洞与整改过程 | 相当于把「已知弱点清单」公开 |

**三个选项**（都不影响仓库可用性）：

1. **保持现状**（默认）：仓库当内部文档用，GitHub 上设 **Private** 仓库，只加协作者。凭据已零明文，私有仓库下这些内部信息不算泄露。
2. **公开 + 匿名化**：把 IP → `10.0.0.10`、`*.corp.local` → `*.example.com`、robot/账号名 → `robot$ci` / `user01`，叙述保留（对读者仍有价值）。可以脚本化批量替换，但会破坏「照着文档就能复现」的价值。
3. **公开 + 拆分**：`docs/` 里的「生产架构 / 凭据总表 / 验收记录」留在私有仓，只把通用部分（流水线设计、GitOps、监控方案）发布到公开仓。

## 4. 会真的导致泄露的四个口子（发仓库之外）

| 口子 | 现在的状态 | 怎么办 |
| --- | --- | --- |
| `.env` 被手动上传/复制 | `.gitignore` 已挡 git，挡不住网盘/微信/邮件 | 只放本机；不进 OneDrive 同步目录；不贴聊天 |
| PowerShell / bash 历史 | 你手敲过 `source`、`kubectl create secret --from-literal` 之类 | PowerShell：`Clear-History` + 删 `ConsoleHost_history.txt`；bash：`history -c`、`unset HISTFILE` |
| 误提交后 `git rm` 也算泄露 | 历史已收口成**单个 commit**（`initial commit`）；修正前那个 commit 里还留着本轮修复的 6 处明文，已经 `git commit --amend` 重写掉了，`git log --oneline` 只有一条。一旦 push 过含 `.env` 或多份未修复版本的提交，删文件也没用 | 用 `git filter-repo --path .env --invert-paths` 重写历史 → 强制 push → **立刻轮换所有口令** |
| GitHub 上的 Secret Scanning / 日志 | GitHub 对 `glpat-`/`squ_`/`ghp_` 等模式会自动告警；Actions 日志也会留痕 | 私有仓库可开 Secret Scanning 自查；不要在 Actions 里 `echo` 密钥 |

另外两条与本仓库无关但同样致命的：**截图**（网页/终端里含口令）和**录屏**。这类文件不要放进 `docs/`——当前仓库里已确认 0 张图片。
