## 4. Windows 本机执行方式

本机没有 `sshpass`，脚本用 paramiko 复用连接，避免反复输密码：

```powershell
cd C:\Users\morning\Desktop\cicd

# 连通性检查
python scripts\tools\ssh_exec.py --ping

# 执行单条命令
python scripts\tools\ssh_exec.py "kubectl get nodes"

# 整段脚本执行（推荐，支持循环/if；含引号或 $ 的命令也必须走 --script）
python scripts\tools\ssh_exec.py --script scripts\argocd\17-final.sh --timeout 200

# 上传文件
python scripts\tools\ssh_exec.py --put "repo-overlay\.gitlab-ci.yml=>/root/podinfo-src/.gitlab-ci.yml"
```

连接参数可用环境变量覆盖（默认 `root/1@192.168.200.12:22`）：

```powershell
$env:SSH_HOST="192.168.200.12"; $env:SSH_PASSWORD="1"; python scripts\tools\ssh_exec.py --ping
```

## 6. GitLab ⇄ ArgoCD 对接实现

### 6.1 ArgoCD 侧仓库凭据

```yaml
# Secret: argocd/gitlab-repo-creds
metadata:
  labels:
    argocd.argoproj.io/secret-type: repository
stringData:
  type: git
  url: http://192.168.200.12/root/cicd-demo.git
  username: root
  password: ${GITLAB_PAT}     # GitLab PAT(api 权限)
```

### 6.2 Application

```yaml
# /root/demo-app.yaml
kind: Application
metadata:
  name: demo-app
  namespace: argocd
spec:
  project: default
  source:
    repoURL: http://192.168.200.12/root/cicd-demo.git
    targetRevision: main
    path: deploy            # 仓库里的 kustomize 目录
  destination:
    server: https://kubernetes.default.svc
    namespace: demo
  syncPolicy:
    automated: { prune: true, selfHeal: true }
    syncOptions: [ CreateNamespace=true ]
```

### 6.3 Webhook（秒级同步）

GitLab 项目 hook：`http://192.168.200.12:30080/api/webhook`（push 事件）。

前置条件：管理后台开启「允许 webhook 请求本地网络」——

```bash
curl -X PUT "http://192.168.200.12/api/v4/application/settings" \
  -H "PRIVATE-TOKEN: ${GITLAB_PAT}" \
  --data-urlencode "allow_local_requests_from_web_hooks_and_services=true"
```

> 踩坑：创建 hook 时如果对 `url` 用 `--data-urlencode`，URL 会被编码成 `%3A%2F%2F`，
> GitLab 直接返回 `Invalid url given`。必须用 `-F "url=..."`（表单字段）提交。

### 6.5 podinfo 的清单分支模型（2026-11-25 改造）

`root/podinfo` 不再是"main 里既放源码又放清单"：

| 分支 | 内容 | 读取方 |
|---|---|---|
| `main` | 源码 + `.gitlab-ci.yml` + `ci/` | Runner 构建 |
| `deploy` | 仅 `deploy/`（podinfo、webapp 的 kustomize） | ArgoCD（`targetRevision: deploy`） |

流水线（**当前 4 stage**）：`quality-gate`（Sonar 扫描 + 门禁）→ `podman build` → push 全 sha tag → `ci/verify-image.sh` 校验 registry 可读 → `artifact-publish`（打 tar.gz + sha256 传 Artifactory）→ `ci/update-manifest.sh` 以远端 deploy 为基重建提交并 push（失败重试 3 次；main 已前进则跳过）。webhook 只由 deploy 分支变化触发。

完整设计、验证记录与排障见 **`docs/02-流水线与交付/GitOps与ArgoCD.md`** 与 **`docs/02-流水线与交付/Sonar与Artifactory.md`**；脚本 `scripts\argocd\228-switch-to-deploy-branch.sh`、`scripts\pipeline\239-state-check.sh`。

## 8. 已知约束与排障

**ArgoCD 中文界面（翻译层）**

ArgoCD 官方 UI 无 i18n：`argocd-server --help` 无 `lang/locale` 参数，镜像内无语言资源，`argocd-cm` 只能注入 CSS 换皮肤。因此中文通过一层 nginx 代理实现：

```
浏览器 → :30082 (nginx, 注入 /zh-cn.js) → argocd-server ClusterIP:80 → :30080 原生英文
```

- 组成：`argocd/argocd-zh-proxy`（nginx:1.27-alpine，ConfigMap 挂载 `nginx.conf` + `zh-cn.js`，NodePort 30082）
- 原理：`sub_filter '</head>' '<script src="/zh-cn.js"></script></head>'` 注入词库；前端脚本用 MutationObserver 按「精确词条 / 去尾冒号 / 全大写不敏感 / 前缀 / 相对时间」规则替换可见文本，跳过 `SCRIPT/STYLE/PRE/CODE/SVG` 等节点，不动应用名、镜像、YAML 等业务数据
- 覆盖：登录页、应用列表/详情、同步状态与健康状态、项目、设置、用户信息、同步与回滚按钮、时间显示等主要界面
- 不覆盖：网络拓扑图内 SVG 文案、第三方图表组件、动态业务值（如 `demo-nginx`、`in-cluster`）
- 重新部署：`python scripts\tools\ssh_exec.py --script scripts\argocd\22-deploy-zh.sh`（改词库后必须 `rollout restart`，因为 `subPath` 挂载不会跟随 ConfigMap 更新）
- 关闭（仅当次浏览器）：控制台执行 `localStorage.setItem('argocd-zh','off')` 后刷新；临时下线整个层：`kubectl -n argocd scale deploy/argocd-zh-proxy --replicas=0`
- 升级 ArgoCD 后：UI 文案可能变化，按需在 `manifests/argocd-zh/zh-cn.js` 的 `DICT` 增补词条并重跑 22 脚本

**网络与镜像源（本机最关键的一条）**

服务器直连 `docker.io`、`github.com` 均不通，实际可用通路：

| 用途 | 可用源 | 不可用 |
|---|---|---|
| K8s 控制面镜像 | `registry.cn-hangzhou.aliyuncs.com/google_containers`（注册到 `--image-repository`） | `registry.k8s.io`（能连通但慢） |
| Docker Hub 镜像 | `docker.m.daocloud.io`（已写入 containerd `registry.mirrors`） | `docker.io` 直连 |
| Calico / ArgoCD | `quay.io`（直连可用） | — |
| GitLab RPM | `packages.gitlab.com`（实测 11–19 MB/s） | Docker Hub 拉 GitLab 镜像（卡在 1.7G 处停滞） |
| 清单文件 | `cdn.jsdelivr.net`、`raw.githubusercontent.com` | — |

**内存与磁盘（当前实测）**

- 节点 16 GiB，已用约 **12 GiB**，可用仅 **2.7 GiB**；根盘 64 GB 已用 45 GB（**72%**，余 19 GB）。这是当前最紧的两项资源。
- 主要占用：GitLab Omnibus ≈3.4 GB、K8s 控制面 + Calico ≈1.2 GB、Keycloak + PG ≈1 GB、SonarQube + PG ≈1 GB、Harbor 7 Pod ≈1.2 GB、Artifactory ≈1 GB、Jenkins ≈0.7 GB、ArgoCD ≈0.6 GB、业务 Pod ≈0.8 GB。
- 已做的节流：GitLab 关 prometheus/kas/pages/registry/mattermost 与各类 exporter；`puma worker_processes=2`、`sidekiq max_concurrency=5`、PG `shared_buffers=256MB`、Redis `maxmemory=256mb`；Jenkins `numExecutors=2`；Runner `concurrent=1`。
- `/data` 占用：harbor 4.0 GB、sonarqube 403 MB、jenkins 304 MB、artifactory 109 MB、keycloak 69 MB、openldap 296 KB。
- 再加负载前先扩容：优先加内存与根盘，或把 `/data` 迁到独立盘；**不要**关 swap（kubelet `failSwapOn: false`，swap 是 OOM 兜底）。
- Sonar 需要 `vm.max_map_count=262144`（`961-deploy.sh` 已持久化到 sysctl），否则 ES 启动即崩。

**自启顺序（重启后约 3–5 分钟全部就绪）**

```
containerd(enabled) → kubelet(enabled) → 静态 Pod(apiserver/etcd/scheduler/controller)
        → Calico → argocd-* Pods → ArgoCD 自动同步 demo-app
gitlab-runsvdir(enabled) → puma/sidekiq/gitaly/nginx ...
```

> 踩坑：早期排查时曾 `systemctl disable kubelet`，导致重启后集群不自启。已重新 `enable`，并在 18 脚本中固化。


**GitLab SSH（22 端口）说明**

Omnibus 安装方式下 GitLab 没有独立 sshd，`gitlab_shell_ssh_port=2424` 仅影响页面显示的克隆地址。
当前**推荐用 HTTP 方式** clone/push（PAT 认证）。若必须用 SSH，需要额外启用 `gitlab-sshd`：

```ruby
# /etc/gitlab/gitlab.rb 追加后 reconfigure
gitlab_sshd['enable'] = true
gitlab_sshd['listen_address'] = '0.0.0.0:2424'
```

**ArgoCD CRD 注解超长**

`kubectl apply` 创建 `applicationsets.argoproj.io` 会报 `Too long: may not be more than 262144 bytes`，
需 `kubectl apply --server-side=true -f /root/argocd-install.yaml`（05 脚本后续步骤已用该方式兜底）。
