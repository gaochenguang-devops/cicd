# 制品归档与拉取方案（Jenkins Archive / Artifactory / Harbor）

> **⚠️ 2026-11-27 起：Harbor 的推/拉地址统一用 `https://harbor.corp.local`**（`EXT_ENDPOINT` 已切成该域名，否则 OIDC 回调对不上、登录报 `redirect_uri`）。本文里的 `192.168.200.12:30090` 属历史记录/直连排障口径；`podman login/push`、`docker pull`、`HARBOR_REGISTRY`、Jib 的 `jib.to.image` 现在都写域名。containerd 侧保留 `192.168.200.12:30090 → https://harbor.corp.local` 别名，老清单不会被拉断。细节见 `docs/03-身份与账号/统一身份SSO-Keycloak.md` §9.5 与 `docs/01-入口与网络/访问层与证书.md` 5.9 第 8 条。

> 适用对象：`maven-demo-pipeline` 这条 Jenkins 流水线，以及同平台的 podinfo/webapp。
> 事实基准：2026-11-26 build #6、#7 实测（`artifact_sha256` 两边一致、`manifest_http=200`）。
> 服务器 `192.168.200.12` 当前不可达时，本文命令需等它恢复后再执行。

## 1. 先分清"归档在哪"——三处各有各的用途

流水线一次成功构建会把同一个交付物放到三个地方，拉取方式完全不同：

| 归档位置 | 内容 | 谁适合拉 | 保留期 |
|---|---|---|---|
| Jenkins 构建归档（`archiveArtifacts`） | `target/maven-demo.jar` | 临时排查、下载某次构建的产物 | **只留 10 次**（`buildDiscarder(numToKeepStr:'10', artifactNumToKeepStr:'5')`） |
| Artifactory `build-artifacts`（Generic 中央仓） | jar + `.sha256` + `build-info.json` | **长期留存、审计、跨流水线取依赖** | 无自动清理（手动/定期清） |
| Harbor `apps/maven-demo` | 运行镜像 `1.0.<N>` | 部署、`docker pull`、K8s 拉取 | 无自动清理 |

关键结论：**Jenkins 归档是"临时"的，长期拉取要认 Artifactory**。`numToKeepStr: 10` 意味着第 11 次构建后 #1 的归档就没了；`lastSuccessfulBuild` 也只是"最近一次成功"，不是"某个固定版本"。

## 2. 拉取入口总览（按场景选一行）

| 场景 | 用什么 | 一条命令（可直接抄） |
|---|---|---|
| 人在浏览器里点一下 | Jenkins UI | `:30088/job/maven-demo-pipeline/<N>/artifact/target/maven-demo.jar` |
| 取最近一次成功构建的 jar | Jenkins permalink | `curl -fsSL -u <user>:<token> .../lastSuccessfulBuild/artifact/target/maven-demo.jar -O` |
| 取指定版本（可长期） | Artifactory | `curl -fsSL -u <user>:<pass> .../artifactory/build-artifacts/maven-demo/main/1.0.6/maven-demo.jar -O` |
| 校验产物没被改过 | Artifactory `.sha256` | `curl ... maven-demo.jar.sha256`，再 `sha256sum -c` |
| 知道这次构建交付了什么 | Artifactory `build-info.json` | 含 build 号、commit、镜像地址 |
| 部署要镜像 | Harbor | `docker pull 192.168.200.12:30090/apps/maven-demo:1.0.6` |
| 下游 Jenkins Job 拿上游产物 | Jenkins + `withCredentials` | 见 5.1 |

## 3. Jenkins 归档怎么拉

### 3.1 URL 结构（最容易踩的一点）

归档路径是**相对于工作区**的，`archiveArtifacts artifacts: 'target/*.jar'` 归档后的相对路径是 `target/maven-demo.jar`，**不是** `maven-demo.jar`。少了 `target/` 这一段直接 404。

```
http://192.168.200.12:30088/job/maven-demo-pipeline/<N>/artifact/target/maven-demo.jar
```

三种构建定位写法：

| 写法 | 含义 | 用途 |
|---|---|---|
| `.../job/.../7/artifact/...` | 第 7 次构建 | 精确、可复现 |
| `.../job/.../lastSuccessfulBuild/artifact/...` | 最近一次成功 | 拿"最新的好的" |
| `.../job/.../lastBuild/artifact/...` | 最近一次（可能失败） | 查失败构建的产物，一般别用 |

### 3.2 认证

Jenkins 开了 `globalMatrix`（`Overall/Read: authenticated`），**匿名拉不到**（返回 403）。两种情况：

```bash
# ① 交互/脚本用（应急账号 breakglass）
curl -fsSL -u 'breakglass:${JENKINS_BREAKGLASS_PASS}' \
  'http://192.168.200.12:30088/job/maven-demo-pipeline/7/artifact/target/maven-demo.jar' -O

# ② 自动化用（推荐：给自己在 Jenkins 里生成一个 API Token，别把口令写进脚本）
curl -fsSL -u '<你的用户名>:<API Token>' \
  'http://192.168.200.12:30088/job/maven-demo-pipeline/lastSuccessfulBuild/artifact/target/maven-demo.jar' -O
```

> GET 下载**不需要 crumb**。只有 POST（触发构建、建 Job）才要 `crumbIssuer/api/json` 取 crumb 并带 cookie。

### 3.3 先看清单再下（避免猜文件名）

```bash
curl -s -u 'breakglass:${JENKINS_BREAKGLASS_PASS}' \
  'http://192.168.200.12:30088/job/maven-demo-pipeline/7/api/json?tree=artifacts%5BfileName%2CrelativePath%5D'
# → {"artifacts":[{"fileName":"maven-demo.jar","relativePath":"target/maven-demo.jar"}]}
```

注意方括号必须 URL 编码成 `%5B` `%5D`，不编码返回空——这和凭据查询是同一个坑。

## 4. Artifactory 怎么拉（长期留存走这条）

### 4.1 路径规则

```
http://192.168.200.12:30092/artifactory/build-artifacts/<app>/<branch>/<version>/<file>
                                          └─ 仓库名（Generic Local）   └ main  └ 1.0.<构建号>
```

例：`build-artifacts/maven-demo/main/1.0.6/maven-demo.jar`。

### 4.2 下载 + 校验（三步，建议固定成脚本）

```bash
APP=maven-demo; VER=1.0.6
BASE="http://192.168.200.12:30092/artifactory/build-artifacts/$APP/main/$VER"
curl -fsSL -u 'admin:${ARTIFACTORY_ADMIN_PASS}' "$BASE/maven-demo.jar"        -O
curl -fsSL -u 'admin:${ARTIFACTORY_ADMIN_PASS}' "$BASE/maven-demo.jar.sha256" -O
sha256sum -c maven-demo.jar.sha256      # → maven-demo.jar: OK
```

`.sha256` 文件里只有一行纯 hash，`sha256sum -c` 直接可用。jar 与 `.sha256` 实测 SHA256 = `997afedd9f9ec0c60fa69209400981a373ebba19ba3e6412056ea037b84a5e81`（1.0.6）。

### 4.3 认证现状（这个 OSS 实例的真实能力）

- **匿名 401**，必须带凭据；
- `admin` 可读可写；
- **LDAP 普通账号只读**：`dev01` 读 jar 返回 200，写返回 403（OSS 没有"按仓库授权"机制，见 `docs/02-流水线与交付/Jenkins流水线.md` 第 8 节）。所以"只读拉取"完全可以用业务账号，不必发 admin。

### 4.4 OSS 的两个限制（拉取侧会撞到）

1. **不能列目录**：`GET .../artifactory/api/storage/<repo>/<path>/?list` → `400 available only in Artifactory Pro`。要看有什么文件，用 `api/storage/<repo>/<path>/<file>` 逐个探（有 `downloadUri` 即存在），或直接相信 `build-info.json` 里的约定文件名。
2. **checksum API 可用**：`GET .../artifactory/api/checksum/build-artifacts/maven-demo/main/1.0.6/maven-demo.jar`，返回 `sha256` 等——不想下 `.sha256` 文件时可走这个。

## 5. 三个可直接复用的调用模板

### 5.1 下游 Jenkins Job 拉上游制品（共享库风格）

```groovy
stage('取上游制品') {
    steps {
        withCredentials([usernamePassword(credentialsId: 'artifactory-admin',
                                          usernameVariable: 'ARTI_USER',
                                          passwordVariable: 'ARTI_PASS')]) {
            sh '''
                set -e
                BASE="http://192.168.200.12:30092/artifactory/build-artifacts/demo-maven/main/1.0.6"
                curl -fsSL -u "$ARTI_USER:$ARTI_PASS" "$BASE/maven-demo.jar" -o maven-demo.jar
                curl -fsSL -u "$ARTI_USER:$ARTI_PASS" "$BASE/maven-demo.jar.sha256" -o maven-demo.jar.sha256
                sha256sum -c maven-demo.jar.sha256
            '''
        }
    }
}
```

关键点：`curl` 一定加 `-f`（HTTP 4xx 直接失败，避免把 401 的 HTML 当 jar 存下来），加 `-L` 跟 302。

### 5.2 Linux 主机/服务器上拉 jar（手工排查用）

```bash
# 拿"最近一次成功"的（注意 Jenkins 只留 10 次，久了会 404）
curl -fsSL -u 'breakglass:${JENKINS_BREAKGLASS_PASS}' \
  'http://192.168.200.12:30088/job/maven-demo-pipeline/lastSuccessfulBuild/artifact/target/maven-demo.jar' \
  -o maven-demo.jar && unzip -l maven-demo.jar | head
```

### 5.3 拉镜像（部署侧）

```bash
# 宿主机（podman/docker 均可）。apps 是私有项目，必须先登录
podman login --tls-verify=false -u 'robot$apps+jenkins-ci' -p '<robot secret>' 192.168.200.12:30090
podman pull --tls-verify=false 192.168.200.12:30090/apps/maven-demo:1.0.6

# 只想知道镜像存不存在（不下载 124MB）
curl -s -o /dev/null -w '%{http_code}\n' -u 'robot$apps+jenkins-ci:<secret>' \
  -H 'Accept: application/vnd.docker.distribution.manifest.v2+json' \
  'http://192.168.200.12:30090/v2/apps/maven-demo/manifests/1.0.6'
# → 200

# K8s 里要拉：Pod/Deployment 必须带 imagePullSecret
kubectl -n <ns> create secret docker-registry harbor-pull \
  --docker-server=192.168.200.12:30090 \
  --docker-username='robot$apps+jenkins-ci' --docker-password='<robot secret>'
```

节点侧 `containerd` 的 `hosts.toml` 里**没有** Harbor 认证配置，所以集群层必须靠 `imagePullSecret`，这一点在 2026-11-26 用临时 pod 验证过（无 secret 超时、有 secret 正常跑出 `openjdk 21.0.13.1`）。

## 6. 拉不到时的对照表

| 现象 | 原因 | 处置 |
|---|---|---|
| `403` / 登录页 HTML | Jenkins 匿名无权 | 带 `-u`，或用 API Token |
| `404`（Jenkins） | 漏了 `target/`，或构建已被 `buildDiscarder` 清掉 | 补相对路径；改从 Artifactory 拉 |
| `404`（Artifactory） | 版本/分支目录写错（`main` 是分支，不是 `master`） | 核对路径 `<app>/<branch>/<version>/` |
| 存下来的文件只有几百字节 | `curl` 没加 `-f`，把错误页存成了"jar" | 一律 `curl -fsSL`，再 `unzip -l` 验一下 |
| `401`（Artifactory） | 没带凭据 / 匿名被关 | 加 `-u`；只读用 LDAP 账号即可 |
| `400 Pro`（Artifactory） | 用了 `?list` 列目录（OSS 不支持） | 改成逐个 `api/storage/.../<file>` 探测 |
| `unauthorized`（Harbor push/pull） | 未登录或 robot 是另一个项目的 | `podman login` 用 `robot$apps+jenkins-ci`；拉基础镜像用 `robot$library+jenkins-lib-pull` |
| `manifest` 请求 401/404 | 少了 `Accept: ...manifest.v2+json` 或 tag 不存在 | 补头，核对 tag 名 |

## 7. 建议的三条纪律

1. **要长期留的东西，只认 Artifactory 路径**（`<app>/<branch>/<version>/`），Jenkins 归档当缓存看；
2. **每次拉完都校验**：`sha256sum -c` 或 Artifactory `api/checksum`，别用"文件大小差不多"判断；
3. **拉取凭据分两类**：读用只读账号（LDAP 业务号或专用只读身份），写只留在 Jenkins 的 Secret 里——当前 Artifactory OSS 无法给非 admin 授写权限，这条只能靠"读/写身份分离 + 写侧只在 CI 容器里"来兜。
